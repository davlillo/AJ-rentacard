# Workshop budgets clarity and additional items
Objective: Make the presupuestos screen understandable and let the operator add a well-defined extra item with its client price as a first-class action.
Branch: feature/pruebas; local only, no commits/push, no database writes or migrations. Checks: isolated tests, synthetic browser fixtures, TypeScript and production build. Engram mirror pending unresolved project identity.

## Specs
- S1: “aun veo desorden en presupuestos” — Reduce visible disorder in the presupuestos workspace: fewer jargon labels, fewer competing sections, one clear path per intent. Keep every existing capability and both cost and client views.
- S2: “yo realizó un presupuesto inicial … el diagnóstico … comprar un motor … cambiar boquillas … veo los costos que se va a llevar el trabajo … a partir de esos costos que yo estimo ya le creo el presupuesto al cliente” — Preserve the cost-first model: internal planned costs are the operator's estimate, the client quote carries manual prices, and neither derives from the other. No automatic margin, no price from cost, unknown cost stays unknown.
- S3: “cuando yo … en la parte de taller y agrego algo más … un parabrisas … de concesión de adicionales … pueda agregar ese precio o ese costo del parabrisas a la parte del presupuesto persona extra como muy bien definido” — Add a first-class action to add an extra item with its own client price to the client quote, so an additional item is a defined line rather than an implicit change. The internal cost of that line stays optional and independent.
- S4: The quote model has no per-line disposition and none may be invented. “Adicional autorizado” stays a cost disposition that references an approved quote version. The extra-item path must use the existing version flow: a new full-scope revision in Borrador that must be approved again by the client before it can be charged. The interface must say this plainly instead of letting the operator believe the extra is already agreed.
- S5: Jargon replacement in the same spirit as the researched cost screen: “Costo previsto” to “Costo interno”, “Margen previsto · interno” to “Margen interno (precio − costo)”, “Por completar” to “Sin costo aún”, “Por definir” to “Sin precio aún”, approver and evidence fields to plain wording. The status filter lists quote states only, and the legacy spreadsheet import becomes a secondary action.
- S6: Keep permissions, guards, optimistic versions, parent-version conflict handling, discount authorization, delivered-order blocking and client-safe exports unchanged. No schema change, no new accounting rule, no stored artifact, no automatic issuance or approval.
