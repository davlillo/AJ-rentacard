Detail modal summarizes that selected entry only.
- S5: “Luego otra pantalla de total de ingresos. De igual forma una tabla donde se define si fue ingreso, de qué tipo de ingreso.” — Financial section uses typed canonical document/application/expense rows with scope-aware amounts, dates and origins. Preserve grouped/shared allocations and restricted access. Do not invent a complete refund/credit cash ledger where the API does not provide one.
- S6: “Luego la parte de documentación.” and “Luego la parte de documentación con un checklist de los documentos que se encuentran. A su vez, ahí mismo debe existir el tab para cambiar entre secciones.” and “Para mí solo eso debería tener la parte de vehículos. Y ya” — Exactly five permanent dossier sections: Resumen, Historial de alquileres, Historial de mantenimientos, Ingresos, Documentación. Checklist shows registered evidence using actual file purposes, not invented legal obligations. Preserve authorized upload/download and administration within these sections/actions without extra tabs.
- S7: Preserve existing scope='order' workflow, permissions, route compatibility and data. New dossier is dispatched explicitly for scope='vehicle', not merely a missing order. Keep keyed loading/stale-response guards. Legacy seccion=Ingresos meant workshop admissions; retain that legacy meaning while giving the new financial tab an unambiguous canonical key.
